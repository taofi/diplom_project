# Plan: Modify Checkout Verification to Support Existing Users

## Objective
Change the checkout verification flow so that when a user with an existing registered email attempts to checkout, a new account is not created. Instead, the purchase (cart items) is added to the existing account, and the user is automatically logged in.

## Background
Currently `CheckoutVerificationService.sendVerificationCode` throws a 409 Conflict if the email already exists. Additionally, `verifyCodeAndCreateAccount` returns an error if the user exists. The new behavior should:
- Allow sending verification code to existing emails without error.
- Upon successful verification, if user exists: log them in, transfer guest orders, sync cart items, and return tokens.
- If user does not exist: create new account as before.

## Changes Required

### File: `server/src/auth/checkout-verification.service.ts`

#### 1. Method `sendVerificationCode` (lines 54-103)
- Remove the block that queries for an existing user and throws `ConflictException` (lines 59-66).
- Keep the rest of the method unchanged (code generation, storage, email sending).

#### 2. Method `verifyCodeAndCreateAccount` (lines 109-289)
- Modify the query for `existingUser` to include roles association: `include: [{ model: this.userRoleModel }]` (currently around line 158).
- Replace the current early return for `existingUser` (lines 162-168) with the following existing user handling logic:
  - Extract roles: `const roles = existingUser.user_roles?.map(ur => ur.role) || ['user'];`
  - Transfer any guest orders associated with this email: `await this.orderService.transferGuestOrdersToUser(existingUser.id, email);`
  - Sync cart items using the same logic as for new users:
    - If `cartItems` provided (from frontend): convert each item to `{ productLicenseId, productId }` by calling `cartService.findProductLicenseId`, then call `cartService.syncCart(existingUser.id, syncedItems, locale)`.
    - Else if `guestId` provided (legacy flow): fetch guest cart via `cartService.getGuestCart(guestId)`, call `cartService.syncCart` with mapped items, then `cartService.clearGuestCart(guestId)`.
  - Generate JWT tokens for the existing user: `const tokens = await this.tokenService.generateTokens({ sub: existingUser.id, email: existingUser.email, roles });`
  - Return success response with user information (id, email, name, roles, locale, avatar_url) and tokens.
- The new user flow (the `else` branch) remains completely unchanged.

## Side Effects & Considerations
- **Security**: Removing the 409 response prevents email enumeration via this endpoint; the response is identical whether the email exists or not.
- **Email**: No "account created" email is sent for existing users (unlike new users).
- **Locale**: The existing user's locale from their profile is preserved; the incoming `locale` parameter is only used for cart item translations.
- **Cart Merging**: Existing user's cart will be merged with the guest cart (if any) without duplicating items, thanks to `syncCart` logic.
- **Token Roles**: Existing users receive tokens containing their actual roles; new users receive `['user']` by default.
- **No Order Creation**: This service does not create an order; after verification, the frontend is expected to call the standard checkout endpoint (`/checkout`) as an authenticated user. The order will then be linked to the user automatically.
