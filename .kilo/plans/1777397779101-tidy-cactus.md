# Plan: Fix File Upload Restriction and Implement Cascade Delete for Product

## Part 1: Allow any file type in UploadFilesModal

### Problem
The document/file input field in `UploadFilesModal.tsx` currently rejects image files. The `handleFileSelect` function checks if the selected file is an image and shows an error "documentOnly", preventing users from uploading images as documents.

### Solution
Remove the validation that prevents image files from being uploaded through the document input. This will allow any file type to be uploaded.

### Changes

**File:** `front/src/components/chat/UploadFilesModal.tsx`

- In `handleFileSelect` (lines 51-64), delete the conditional block that checks `selectedFile.type.startsWith('image/')` and returns early with an error.
- The function should directly set the selected file.

**Before:**
```typescript
const handleFileSelect = useCallback((e: React.ChangeEvent<HTMLInputElement>) => {
  const selectedFile = e.target.files?.[0];
  if (!selectedFile) {
    return;
  }
  if (selectedFile.type.startsWith('image/')) {
    setError(t('chat.errors.documentOnly'));
    return;
  }
  setFile(selectedFile);
  if (fileInputRef.current) {
    fileInputRef.current.value = '';
  }
}, [t]);
```

**After:**
```typescript
const handleFileSelect = useCallback((e: React.ChangeEvent<HTMLInputElement>) => {
  const selectedFile = e.target.files?.[0];
  if (!selectedFile) {
    return;
  }
  setFile(selectedFile);
  if (fileInputRef.current) {
    fileInputRef.current.value = '';
  }
}, [t]);
```

### Impact
- Users can upload any file type (including images) through the document upload field.
- The separate image upload section (with `accept="image/*"`) remains unchanged and still only accepts images.

## Part 2: Implement Cascade Delete for Product and Related Entities

### Problem
Deleting a product fails with a foreign key constraint violation:

```
SequelizeForeignKeyConstraintError: update or delete on table "product_licenses" violates foreign key constraint "order_items_product_license_id_fkey" on table "order_items"
```

The `ProductRepository.delete` method manually deletes `product_licenses`, but rows in `order_items` (and potentially `cart_items`, `user_products`) still reference those licenses, causing the error.

### Goal
Ensure that when a product is deleted, all related data is automatically removed via cascading foreign key deletes, maintaining referential integrity and preventing constraint violations.

### Approach
Add `onDelete: 'CASCADE'` to all Sequelize foreign key definitions that point to tables which should be deleted when their parent is deleted. Then apply these changes to the database via a migration (or synchronize if using `alter: true`).

### Model Changes

Add `{ onDelete: 'CASCADE' }` as the second argument to the `@ForeignKey` decorator in the following files:

### Database Migration

After updating the models, the foreign key constraints in the database must be altered to include `ON DELETE CASCADE`.

**Option A: Using Sequelize CLI (recommended for production)**
1. Generate migration: `npx sequelize-cli migration:generate --name add-cascade-deletes`
2. Edit the generated file. In the `up` method, use raw SQL to drop and recreate each constraint with `ON DELETE CASCADE`. Example:

   ```typescript
   await queryInterface.sequelize.query(`
     ALTER TABLE "order_items"
     DROP CONSTRAINT "order_items_product_license_id_fkey",
     ADD CONSTRAINT "order_items_product_license_id_fkey"
       FOREIGN KEY ("product_license_id") REFERENCES "product_licenses" ("id") ON DELETE CASCADE;
   `);
   ```
   Repeat for each table (see constraint names below). The `down` method should reverse these changes.

3. Run migration: `npm run migration:run` (or the project's migration command).

**Constraint names** (inferred from typical Sequelize naming; verify against actual DB):
- `order_items`: `order_items_product_license_id_fkey`
- `cart_items`: `cart_items_product_license_id_fkey`
- `user_products`: `user_products_product_license_id_fkey`
- `product_licenses`: `product_licenses_product_id_fkey`
- `product_media`: `product_media_product_id_fkey`
- `product_translations`: `product_translations_product_id_fkey`
- `product_categories`: `product_categories_product_id_fkey`
- `chat_rooms` (product_id): `chat_rooms_product_id_fkey`
- `chat_rooms` (user_product_id): `chat_rooms_user_product_id_fkey`
- `offers`: `offers_chat_room_id_fkey`
- `offer_files`: `offer_files_offer_id_fkey`
- `chat_messages`: `chat_messages_chat_room_id_fkey`
- `chat_message_attachments` (chat_message_id): `chat_message_attachments_chat_message_id_fkey`
- `chat_message_attachments` (chat_room_id): `chat_message_attachments_chat_room_id_fkey`

**Option B: Synchronize (development only)**
If the project uses `synchronize: true` in the Sequelize config, you may restart the server after model changes. However, altering foreign key constraints via `sync({ alter: true })` is not guaranteed; using a migration is safer.

### Testing
- Attempt to delete a product that has associated licenses, order items, cart items, etc.
- Verify the product and all related records (licenses, order items, cart items, user products, media, translations, categories, chat rooms, messages, attachments, offers, etc.) are removed.
- Confirm no foreign key constraint errors occur.
- Check edge cases: product with no related data should still delete cleanly.

### Important Notes
- **Data Loss**: Cascade deletion is destructive. All data related to the product will be permanently deleted, including order history, chat logs, and user product entitlements. Ensure this is the intended business behavior.
- Existing manual deletion code in `ProductRepository.delete` will continue to work but is now redundant for tables covered by cascade. It can be simplified in a future cleanup.
- Ensure that all developers running the application apply the migration to keep database schemas in sync.
